# Storage and database bootstrap

Only new uploads use Supabase Storage. The empty baseline creates `public-assets` (public images) and `course-content` (private videos, text notes, PDFs). The backend prefers `SUPABASE_SECRET_KEY`, with legacy service-role fallback; never expose either in the browser. Content rows store `storage://course-content/<key>` references, and authenticated endpoints issue short-lived signed URLs. Existing `/uploads/...` or Cloudinary URLs are **not** migrated automatically: inventory/copy originals, update `content.file_url` after verifying checksums/ownership, and remove old hosting separately. Until migrated, legacy references fail closed.

Do not apply the inconsistent `supabase/migrations/0000`–`0013` history. For the confirmed empty project, use `npm run db:check-empty` then `npm run db:apply-empty` with the explicit project-ref env and verified TLS. See `sql/EMPTY_BOOTSTRAP.md` and root `docs/environment-setup.md`. `npm run db:bootstrap` remains offline SQL generation only. The canonical baseline includes core/payment/report/library tables, corrected doubt FKs/checks, payment indexes, RLS and bucket configuration. Never replay legacy/additive migrations alongside it. Existing populated projects need separately reviewed additive migrations. Optional demo seeding is never a reset and requires a locally chosen password.

The canonical baseline enables RLS on all app tables and revokes anon/authenticated table privileges. The application connects using a trusted server-side database role. Do not also apply older RLS scripts to this baseline. Never expose database/server keys to browsers; any future browser-direct access needs explicit scoped policies, not broad `USING (true)` policies.

In Supabase Storage create `course-content` as **private**, with no anonymous SELECT/INSERT/UPDATE/DELETE policies. Create `public-assets` as public only for intended non-sensitive thumbnails/images, restrict writes to the backend service role, and review bucket MIME types and file-size caps. Do not make `course-content` public or add broad object policies; the backend checks entitlement before returning signed URLs. Verify bucket visibility and an unauthorized access attempt in a staging project before serving real files.
